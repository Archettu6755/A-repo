# 浏览器交付协议

## 1. 文档目的

本文档规定游戏浏览器版本的产品边界、构建方式、发布方式和验收条件。浏览器版本是现有桌面版本的附加交付形式，不替代 Python、pygame-ce 和 uv 组成的开发环境。

玩法、地图、数值和美术继续以 `docs/proposal.md`、`docs/map.md` 和 `docs/art.md` 为准。本文档只规定浏览器交付。后续经用户确认的新要求可以覆盖本文档中的旧约定，覆盖后必须同步修改本文档。

## 2. 交付目标

浏览器版本面向不了解 Python、uv、pygame、Git 和命令行的参与者。参与者通过网址打开游戏，等待资源加载完成后即可游玩。

正式交付使用 GitHub Pages 托管静态文件。游戏逻辑在参与者的浏览器内运行，不连接本地 Python 进程，也不依赖业务后端。

参与者的操作流程固定为：

```text
获得游戏网址
-> 使用浏览器打开网址
-> 等待游戏加载
-> 点击游戏画面或按任意键开始
```

参与者不需要执行安装命令，不需要下载项目源码，也不需要启动本地服务器。

## 3. 系统结构

浏览器版本使用 pygbag 0.9.2 将 Python 和 pygame-ce 游戏打包为浏览器可运行的 WebAssembly 应用。0.9.3 的官方模板在当前运行时会请求已经移除的 BrowserFS 文件并停在加载画面，因此在上游问题修复前不得擅自升级。

构建与发布过程如下：

```text
GitHub 仓库中的正式代码
-> GitHub Actions 创建浏览器构建
-> GitHub Pages 发布静态文件
-> 浏览器加载 HTML、WebAssembly、字体和游戏资源
-> 游戏逻辑在浏览器本地执行
```

GitHub Pages 只提供静态文件，不处理关卡、敌人、碰撞、金币、商店和状态切换。当前版本不设置数据库、账号服务、排行榜服务或远程存档服务。

## 4. 参与者环境

### 4.1 必需条件

- 一台能够运行现代浏览器的普通电脑、手机或平板。
- 可访问 GitHub Pages 交付网址的网络连接。
- Windows 电脑使用 Chrome 或 Edge。
- Android 手机和平板使用 Chrome，并以横屏游玩。
- iPad 使用 Safari，并以横屏游玩。
- 电脑键盘的方向键、F、E 和 ESC 可以正常使用。
- 触摸设备支持多点触控。

### 4.2 不需要的条件

- 不需要安装 Python。
- 不需要安装 uv。
- 不需要安装 pygame-ce 或 pygbag。
- 不需要安装 Node.js 或其他前端工具。
- 不需要打开 PowerShell、终端或命令提示符。
- 不需要独立显卡。
- 不需要管理员权限。

Windows Firefox 和 iPhone Safari 作为尽力兼容目标，不作为首个浏览器版本的阻塞项。手机和平板只提供横屏游戏布局，竖屏时显示转为横屏的提示。

## 5. 代码复用与平台边界

桌面版和浏览器版必须共用玩法代码。关卡生成、实体、碰撞、敌人行为、商店、UI 和数值配置不得各自维护一套实现。

浏览器适配可以增加以下平台代码：

- 浏览器专用的 `main.py` 入口。
- 支持浏览器事件循环的异步运行接口。
- GitHub Actions 构建与发布配置。
- 浏览器资源整理脚本。
- 浏览器平台检测、触摸控制层和少量输入兼容代码。

游戏主循环必须允许浏览器在每帧取回控制权。异步化不得改变桌面版的帧更新顺序、输入语义和游戏状态流。

桌面版继续支持：

```powershell
uv run game
```

浏览器适配完成后，桌面版原有测试必须继续通过。

## 6. 资源规则

浏览器构建只包含运行游戏所需的文件。`tools/build_web.py` 按运行时代码使用的资源清单整理图片、字体和音频。美术母版、独立帧备份、未使用的 UI 变体、设计源文件、测试截图、开发文档和构建缓存不进入网页资源包。

浏览器版本必须随包提供中文字体，不得依赖参与者电脑中的 Windows、WSL 或 Linux 系统字体。桌面版与浏览器版应当优先加载同一份项目字体。

资源路径统一使用跨平台路径处理，不在网页构建中写入 Windows 反斜杠路径。图片、字体和其他静态资源在游戏开始前完成加载，加载失败时应当给出可见错误，不得只显示空白或黑屏。

## 7. 操作与显示

### 7.1 电脑键盘

电脑浏览器沿用正式操作约定：

| 按键 | 功能 |
| --- | --- |
| 方向键 | 上下左右移动 |
| F | 向当前朝向射击或确认菜单选项 |
| E | 打开或关闭属性面板 |
| ESC | 暂停、返回或关闭面板 |
| 任意键 | 在标题、失败和开发中提示画面继续 |

不得增加 WASD 作为默认移动方式。网页获得键盘焦点后，方向键不得滚动外部页面。页面首次打开时可以要求参与者点击游戏画面，以满足浏览器的焦点和媒体播放限制。

没有触摸输入的电脑不显示虚拟控制按钮。支持触摸和键盘的设备可以同时保留两种输入，两种输入必须写入同一套游戏指令状态。

### 7.2 手机和平板触摸

触摸设备使用固定虚拟按钮，不使用模拟摇杆：

| 触摸位置 | 功能 | 对应键盘输入 |
| --- | --- | --- |
| 左下角 | 上、下、左、右十字键 | 方向键 |
| 右下角 | 大号射击按钮 | F |
| 射击按钮上方 | 属性按钮 | E |
| 右上角 | 暂停按钮 | ESC |

标题、失败和开发中提示画面允许点击游戏区域继续。商店使用虚拟十字键的上、下选择商品，使用射击按钮购买或确认，使用暂停按钮离开。

触摸输入必须支持一只手指按住方向、另一只手指同时射击。每根手指按下、移动和抬起时分别维护对应按钮状态。收到触摸取消、页面失去焦点或游戏暂停事件时，必须清空全部触摸状态，不能让角色在松手后继续移动或射击。

虚拟按钮使用半透明显示，位于独立的网页控制层。控制层只向游戏发送与键盘相同的方向、射击、属性和暂停指令，不得另写一套移动、菜单或战斗逻辑。网页必须阻止控制区域触发页面滚动、缩放、文字选择和浏览器手势。

### 7.3 方向与缩放

游戏内部逻辑分辨率保持 1280x720。网页可以等比例缩放画布以适应浏览器窗口，但不得拉伸画面、改变 16:9 比例、改变碰撞坐标或重新排布游戏 HUD。

手机和平板只支持横屏游玩。设备处于竖屏时暂停游戏更新并覆盖显示“请将设备横过来游玩”。转为横屏后恢复原有状态，不重新生成关卡。

横屏页面根据可用宽度放置虚拟按钮。宽屏设备优先使用画布两侧的空白区域；没有足够侧边空间时，按钮可以覆盖画面底部两角，但不得覆盖左上角红心、右上角关卡文字、暂停菜单或商店选项。

## 8. 功能范围

浏览器首个正式版本必须包含桌面版当前已有的完整流程：

- 标题画面。
- 三个正式关卡。
- 普通、快速和重型僵尸。
- 房间照明、碰撞、箱子、金币和商店。
- 暂停、属性、失败和重新挑战流程。
- 第三关商店后的两阶段 Boss 战。
- Boss 死亡效果和“后续内容正在开发”提示。
- 任意键返回标题画面。

浏览器版本不是玩法演示，不得删减房间、敌人、关卡、商店或正式 UI 来换取网页运行。

## 9. 数据与网络

当前游戏状态只保存在浏览器内存中。刷新或关闭页面可以结束本局，不提供长期存档。

浏览器版本不得内置私有 API 密钥，不向第三方上传操作记录、设备信息或游戏状态。除加载 GitHub Pages、WebAssembly 运行时和静态资源外，游戏运行时不发起其他网络请求。

以下功能需要单独讨论，不因浏览器发布而自动加入：

- 账号和登录。
- 云存档和跨设备同步。
- 在线排行榜。
- 多人游戏。
- 在线 AI 接口。
- 数据分析和行为统计。

## 10. 自动构建与发布

GitHub Actions 负责安装构建工具、生成网页资源并发布 GitHub Pages。Python、uv 和 pygbag 只存在于开发电脑或 GitHub Actions 环境中，不进入参与者的操作步骤。

推送到 `main` 后自动执行 `.github/workflows/pages.yml`。维护者也可以在 GitHub Actions 页面手动触发同一工作流。网页构建产物位于 `build/web/`，该目录不提交到 Git，由 Actions 作为 Pages artifact 上传并发布。

自动构建至少执行以下检查：

- Python 测试通过。
- Ruff 检查通过。
- 浏览器入口和必需静态资源存在。
- 中文字体包含在交付资源中。
- 网页构建成功生成。

发布失败时不得覆盖最后一个已经通过检查的网页版本。

## 11. 最小交付物

浏览器版本完成时至少提供：

- 默认 GitHub Pages 游戏网址 `https://archettu6755.github.io/A-repo/`。
- 一个浏览器入口文件。
- 一套 GitHub Actions 构建与发布配置。
- 一份随游戏发布的中文字体。
- 一套横屏触摸控制层和竖屏提示界面。
- 浏览器构建所需的资源整理配置或脚本。
- README 中面向参与者的网页启动说明。
- 面向开发者的网页构建和故障排查说明。

生成的网页包是构建产物。是否把构建产物提交到仓库，应在实现时根据 GitHub Pages 发布方式确定，不能同时维护两份手工修改的网页文件。

## 12. 验收标准

浏览器版本必须满足以下条件：

1. 在未安装 Python、uv 和 pygame-ce 的 Windows 电脑、Android 触摸设备和 iPad 上可以通过网址打开。
2. 参与者不需要运行命令或启动本地服务。
3. 标题画面、中文文字、美术资源和红心 HUD 正常显示。
4. Windows Chrome 和 Edge 中的方向键、F、E 和 ESC 与桌面版行为一致。
5. Android Chrome 和 iPad Safari 可以在横屏下使用虚拟十字键移动，并在移动时同时按住射击按钮。
6. 触摸设备的属性、暂停、商店选择、确认和返回操作可以完成，不需要外接键盘。
7. 触摸结束、页面失焦、设备转向和暂停后不会出现持续移动或持续射击。
8. 竖屏设备暂停游戏并显示横屏提示，转为横屏后继续当前状态。
9. 可以从第一关开始，完成三个关卡和两阶段 Boss 战，并在 Boss 死亡效果结束后进入开发中提示。
10. 游戏数值、房间数量、敌人数量和敌人生命与正式协议一致。
11. 浏览器版运行时不依赖业务后端。
12. 页面刷新后可以重新加载游戏，不出现永久黑屏或损坏状态。
13. 浏览器控制台没有阻止游戏继续运行的异常。
14. 桌面版继续可以通过 `uv run game` 启动，原有自动化测试继续通过。

## 13. 当前不包含的交付形式

以下内容不属于首个浏览器版本：

- 本地 HTTP 转发启动器。
- 完全离线的浏览器 ZIP。
- PWA 安装和离线缓存。
- Windows 安装包或 Microsoft Store 发布。
- macOS 和 Linux 本地启动器。
- 手机和平板竖屏游戏布局。
- iPhone Safari 的完整流程验收。
- 面向参与者的本地网页构建工具。

如果后续需要离线课堂环境，可以在本协议基础上增加独立的离线交付协议，不直接改变在线版的产品边界。

## 14. 已确认的发布设置

- 使用仓库默认域名 `https://archettu6755.github.io/A-repo/`，当前不配置自定义域名。
- 每次推送 `main` 后自动测试、构建和发布，同时保留手动触发入口。
- CPython 和 pygame-ce WebAssembly 运行时使用 pygbag 0.9.2 对应的官方 CDN `https://pygame-web.github.io/archives/0.9/`。
- 游戏代码、字体和美术资源由本仓库的 Pages 站点提供，运行时 CDN 不保存游戏关卡、操作记录或游戏状态。
